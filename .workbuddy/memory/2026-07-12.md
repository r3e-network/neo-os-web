# 2026-07-12

## 抓大鹅 (zhuada-e) 玩法与平衡性评审
- 定位：apps/zhuada-e，3D 物理三连消除（类似羊了个羊）+ 大鹅收集。核心玩法在 src/logic/engine-zhuada.ts，引擎/状态机在 guest-engine.ts，曲线在 game-rules.ts，场景/大鹅在 scenes.ts。
- 关键发现：
  1. 无计时模式道具返还饥饿——加时里程碑只在 timedMode 发放，无计时玩家中段拿不到移出/撤回返还（反向经济，P0）。
  2. L1→L2 难度悬崖（物品 18→84、种类 3→7），新手最大流失点（P0）。
  3. 大鹅纯装饰无机制价值；无每日/赛季循环 → 长期留存弱。
  4. 做得好：多重-of-3 可解性、侧架跨区匹配、物品流分包防埋死、L1 数学胜利地板、连击窗口 2200ms 手感优先。
- 交付：docs/zhuada-e-game-design-analysis.md（含难度曲线图、平衡性电子表格、6 条改进提案 R1-R6 + 优先级）。
- 建议：P0 先改 R1（untimedRefund 改发移出/撤回）+ R2（L2 降到 5 类或插过渡关）。

## 已实施 R6（连击 Frenzy）
- 设计：combo≥5 触发**狂潮**，发 2 发"自动吸附"充能（FRENZY_TRIGGER_COMBO=5、FRENZY_CHARGES=2，均 [PLACEHOLDER] 待 playtest）；之后每次消除消耗 1 充能、从盒内自动吸附 1 个刚消除的同色进托盘（省点击+爆发）。无副本/托盘满则回退充能，绝不堵托盘/递归/破可解性；长链再冲 5 重新发。
- 实现：guest-engine.ts 加 applyFrenzyPull 闭包（取盒内副本置托盘，失败回退；不碰 combo/score、不递归）；extract 匹配分支做充能/消耗；胜利判定改读实时可观察量（吸附吸空盒也能判胜）。main.tsx 加 frenzyCharges/frenzyFx 可观察量并接入引擎+state。PlayArea.tsx HUD 紫罗兰"狂潮 xN" + 一次性"FRENZY!"爆发闪层；PlayArea.scss 用 --goose-motion-* 缓动并尊重 prefers-reduced-motion；messages.ts 加 frenzyLabel/frenzyBurst。
- 关键坑：胜利判定原本用闭包开头捕获的 list，会漏算 Frenzy 吸附；必须读 live observables。motion-quality 测试禁止裸 ease-out，故爆发用 var(--goose-motion-celebrate)。
- 测试影响：原"全波次抽干只在全空判胜"的 14 个关卡测试用贪婪"只看盒内"解算器，会被 Frenzy 残留托盘组卡住且 extracted===expectedTotal 不再成立。已升级为"先收尾托盘/侧架残留组"的合格解算器 + 放宽 extracted<=expectedTotal。新增 R6 Frenzy 3 用例（发充能+爆发 / 武装匹配吸附扣充能 / 耗尽后重发）。
- 验证：tsc --noEmit 0 错误；eslint 干净；run-tests 全部逻辑测试 150 项全过（guest-engine.test.ts 147→150）。
