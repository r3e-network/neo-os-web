## 1. 产品定义

### 1.1 一句话玩法

玩家从真实碰撞、滚动和遮挡的一篮物件中抽出目标，放进固定七格托盘；三个同款先归组高亮，再清除并左移补位。清空当前关卡的全部逻辑物件后抓住大鹅，托盘塞满且救援耗尽则失败。

### 1.2 乐趣假设

核心张力来自三件事：

1. 近顶视角下的观察与空间判断；
2. 七格托盘的短期规划；
3. 抽走底层后，剩余物件因质量、摩擦和碰撞重新翻滚所产生的不可完全预测性。

长关卡不会一次把数百个刚体塞进画面。玩家持续清出空间，新的完整三元组从底部储备区涌出，形成“越挖越有”的长局节奏。

### 1.3 产品边界

- 免费、本地、无链上结算；关卡生成、三消、计时、存档均在当前页面完成。
- 不复制商业游戏的品牌、角色、模型、贴图、音频、广告或界面装潢；只采用通用的抽物与三消规则。
- 本版本不接入钱包或在线排行榜；抽屉只展示同模式、同关卡的本机最佳分、尝试和通关次数。
- `neo-manifest.json` 明确声明 `offlineSupport: false`：本版本不承诺首次离线启动或 Service Worker 离线包。

## 3. 移动端构图与可访问性

### 3.1 单屏结构

从上到下为：紧凑 HUD → 近顶视物理容器 → 必要的三格悬浮暂存位 → 单排七格托盘 → 五个常驻道具按钮；限时模式再加入“加时”作为第六个按钮。不存在上下各一排托盘，也不把玩法区和按钮区拆成两套视觉系统。

- 目标视口：用户参考视频的 308×720，以及常见手机 390×844。
- 主容器占可用宽度约 93%–98%，视角接近垂直向下，篮沿只做边界框定，不遮挡下半区物件。
- 相机使用 34° 透视投影；高度根据水平视野和关卡容器尺寸计算，窄屏与宽屏都能看完整个容器。
- 物理容器尺寸真实随 `boxSize` 9→12 增长，半宽约 2.79→3.72，浅壁高约 0.78→0.885；不再是旧文档所述固定盒体。

### 3.2 输入与辅助能力

- 指针、触屏与笔统一走 `pointerdown`；射线递归命中子网格并回溯到物件根节点。
- 画布可获得键盘焦点；Enter/Space 抽取当前最高可用物件。
- 状态、计时、托盘、暂存位、工具栏和抽屉具有明确语义与 live region 通知。
- 关键触控目标至少 44px，并提供 `:focus-visible` 样式。
- `prefers-reduced-motion` 时关闭装饰性的镜头微震、颠锅位移、提示脉冲和鹅 bob；权威物理与玩法结果保留。
- WebGL context 丢失时显示可读的恢复/重试状态，不让整个宿主无提示崩溃。
- 第一关在物理画面内用不阻塞输入的三步提示教学：首次点选后进入“三个同款”提示，首次三消后提示“晃一晃/甩手机”，完成动作或继续推进后自动退场；第二关及以后不重复打扰。

## 4. 核心规则

### 4.1 抽取与三消

1. 玩家只能选中射线最前方的可见实体；完全被遮挡的物件不可穿透选择。
2. 逻辑引擎通过 `itemId` 查询权威 `kind`，不信任 UI 传入的种类。
3. 抽出的物件先按托盘当前稳定顺序左压缩；若托盘已有同款，新物件插入该组后方，右侧物件平移让位；否则进入最左侧空位。
4. 托盘与三格暂存位共同计数；同款达到三个时规则立即结算，表现层先把三件归组并高亮，再清除和左补位，优先清暂存位。
5. 当前活动堆、底部储备、托盘和暂存位全部清空才算通关。
6. 托盘 7/7 且没有三元组时，若“移出”或“撤回”仍可用则进入救援态；救援耗尽才判定 `trayFull`。

### 4.2 模式

- 默认休闲模式：无倒计时，唯一失败原因是托盘卡死。
- 可选限时挑战：大厅局间开关；关卡时间随逻辑物件总量增长；最后 10 秒进入危险态，最后 5 秒有滴答音。
- 切到后台时限时模式顺延 deadline，避免后台消耗计时；恢复前一物理帧的超大 delta 会被丢弃。
- 第一次失败可使用本局唯一一枚救援羽毛：托盘卡死时腾回 3 格并把对应物件送回流送池；超时时追加 30 秒。继续不会重置盘面，第二次失败不再提供继续。

### 4.3 道具

| 道具 | 每关初始量 | 规则 |
|---|---:|---|
| 移出 | 1 | 托盘前 3 件移到三格暂存位；暂存位须全空且托盘至少 3 件 |
| 撤回 | 1 | 上一次未触发三消的抽取回到逻辑堆并从顶部安全重落 |
| 洗牌 | 1 | 重分配活动物件种类并重新落料；仍保持三元组可解不变量 |
| 提示 | 3 | 优先提示能补三或形成二连的可见物件 |
| 加时 | 1（仅限时） | 当前 deadline 增加 15 秒；休闲模式不显示、不授予 |
| 颠锅/晃一晃 | 冷却制 | 不消耗次数；5 秒玩法冷却；按钮始终作为传感器不可用时的回退 |

分数达到本关基础分上限约 30% 的倍数时回赠提示；限时模式达到约 60% 的倍数时回赠加时；四连消回赠提示。

### 4.4 随机新局

每次 `startLevel` / 重开都会生成新 salt：

- 对该主题当前章节策划的 12/18 种物件池重新洗牌，并按关卡种类数选择子集；
- 每种物件仍按完整三元组生成，保证逻辑总数可被三消清空；
- 三元组包、开局包、储备包和补货波次重新洗牌；
- 3D 落点、初始朝向、角速度以及底部涌现位置重新计算。

因此同一关连续开局不会复用固定摆法。测试可注入确定性 RNG 复现问题，但普通玩家运行使用 Web Crypto 派生的新种子。

### 5.1 物件流送协议

- 开局最多激活 48 个真实 cannon-es 刚体，其余仅作为廉价逻辑对象保留在 `reserve`。

## 6. 物理、视角与颠锅

### 6.1 物理基线

- 物理世界使用 `world.step(1/60, min(rawDt, 0.1), 3)`，避免高刷新率双速和后台恢复爆炸。
- 54 个物件配置覆盖 produce、ceramic、metal、wood、fabric、paper、glaze 七类表面；质量、摩擦、回弹和复合碰撞体不同，可呈现滚动、翻面、挤压和重量差。
- 容器四壁与底面持续约束刚体；物件允许休眠，抽走支撑后才重新唤醒并下落。
- `powerPreference: high-performance`，关闭不需要的 stencil；模板几何复用降低长局波次反复生成的内存和 GC 压力。

### 6.2 手机传感器

手机动作功能必须由可见按钮显式开启，不会在进入页面时暗中请求权限。

- iOS：在用户手势中调用 `DeviceMotionEvent.requestPermission()`。
- Android/其他支持端：监听 `devicemotion`；2.2 秒未收到首个事件时标记为 blocked 并退回屏幕按钮。
- 直接线性加速度可用时优先使用；只有含重力数据时，以低通估计重力后计算线性分量。
- 单次强动作阈值为 19；轻动作需在 420ms 内连续两次超过 10.5；回落到 3.2 以下才重新武装；检测器内部 refractory 为 900ms。
- 权威玩法冷却为 5 秒，不论来自传感器还是屏幕按钮都统一经过该门禁。

动作强度连续钳制为 0.65–1.35：

| 输出 | 轻甩 | 重甩上限 |
|---|---:|---:|
| 受影响物件比例 | 48% | 100% |
| 水平冲量 | 1.15 | 2.20 |
| 垂直冲量范围 | 1.75–2.70 | 3.30–4.25 |
| 最大角速度 | 3.3 | 6.0 |
| 水平速度硬上限 | 3.8 | 3.8 |
| 垂直速度硬上限 | 5.35 | 5.35 |

物理冲量负责真实翻动；820ms 的容器/物件整体倾斜与回弹负责“颠锅”观感，420ms 微镜头震动负责打击感。视觉幅度随动作增强，但物理速度上限固定，防止重甩把物件发射出容器。`prefers-reduced-motion` 下只保留权威物理翻动。

### 7.1 动画

- 开局顶部落料、储备底部涌现、物件滚动/翻转/休眠。
- 点按有短 press 反馈；物件以 692ms 的可读弧线飞入托盘并轻微缩放/旋转，便于玩家看清来源和落点。
- 三消使用 692ms 入槽、620ms 归组、240ms 高亮、420ms 清除、460ms 补位的阶段编排；总视觉编舞约 1812ms，不会瞬间跳没。
- 托盘和按钮反馈只使用 transform/opacity/filter 等合成层友好的属性；关键移动使用 `translate3d`、`will-change`、局部 `contain: layout paint` 和自然 cubic-bezier，避免布局属性动画、`transition: all` 或瞬间跳变。3D 侧由 `src/scenes/scene-motion.ts` 集中约束 420ms 镜头微震、820ms 颠锅、飞入托盘弧线和按压反馈幅度。
- 暂存跨区消除、提示发光、洗牌重落。
- 颠锅倾斜/回弹、胜利大鹅、失败盖章和主题切换反馈。

### 7.2 音频

正式资源为 15 个原创 mono 22.05kHz / 16-bit PCM WAV：

- 12 个 cue：`land`、`pick`、`match`、`combo`、`win`、`fail`、`powerup`、`shuffle`、`click`、`tick`、`unlock`、`shake`；
- 3 个约 6 秒的循环环境音：garden、kitchen、night。

AudioContext 只在首次用户手势后解锁。PCM cue 尚未解码、拉取失败或离线缓存不完整时，内置 WebAudio 合成器可立即回退；这不等同于承诺整个应用支持离线首启。静音状态持久化，主题环境音随主题切换，页面隐藏时明确暂停且只在活动未静音局恢复；落地声有速度门槛与 45ms 节流，避免高密度碰撞炸音。

### 7.3 触觉

支持端使用 `navigator.vibrate`：pick 10ms、match 30ms、win `[30,50,80]`、fail 100ms、shake `[18,35,28]`。玩家可独立关闭并持久化；iOS Safari 等不支持端静默降级。

## 8. 进度、恢复与个人记录

### 8.1 进度 v3

`zhuada-e:progress` 保存：

- 最高解锁关、最后游玩关、最后主题；
- 每关尝试、失败、通关次数；
- 休闲/限时分离的最佳分；
- 总胜场、兼容最佳分和九只限定大鹅收藏。

v1/v2 会迁移到 v3；写入采用主记录 + backup。遇到未来 schema 时只读展示，旧客户端不会覆盖新数据。Standalone 使用 Web Storage；宿主 opaque-origin sandbox 在启动前通过只允许 `zhuada-e:*` 的 postMessage 桥预热同步镜像，宿主再以 `appId + key` 双重命名空间保存在当前浏览器。存储不可用时本局仍可玩，并显示非阻塞警告，Device QA 判为失败。

### 8.2 中断局恢复

活动局以 140ms debounce 保存逻辑快照，并在 `pagehide` / 页面隐藏时刷新。快照包含活动物件、储备、托盘、暂存位、分数、道具、计时、颠锅冷却、主题和模式；TTL 为 24 小时。大厅明确提供“继续”与“放弃”操作，恢复时以安全的顶部重落重建 3D 堆，不序列化 cannon 世界内部状态。

### 8.3 个人记录口径

个人最佳分按 `mode + level` 分离，三套主题共享同一关卡记录；同时保留每关尝试、失败和通关次数。没有网络提交、钱包身份或伪装成在线服务的空榜。未来如接入排行榜，必须先完成匿名身份、防刷、服务端 board key 与隐私策略设计。

### 9.1 仓库门禁

`npm run verify:release` 顺序执行：

1. Vitest：规则、24 关流送排空、随机重开、传感器阈值、颠锅上限、物理 profile、射线、主题、音频、进度迁移/备份/恢复、个人记录、WebGL context loss 与可访问交互；

4. `npm audit --omit=dev`；
5. 确定性美术/音频再生成；
6. 78 图片 + 15 PCM + 20 源图哈希 + notice/version 校验；
7. `tsc --noEmit` 与 Vite production build。

详细状态与证据边界见 `apps/zhuada-e/PRODUCTION-READINESS.md`、`REFERENCE-VIDEO-AUDIT.md` 和 `design-qa.md`。

### 9.2 发布定义

浏览器自动化通过不等于真机生产放行。正式发布前必须至少在一台 iPhone 与一台 Android 中端设备完成：传感器授权/拒绝/blocked 回退、轻甩/重甩、音频解锁与混音、触觉、60 秒性能、长局内存、转屏/后台恢复、完整胜负与重开。缺任一类证据时状态为“有条件生产候选”，不能标记为“真机验收完成”。
