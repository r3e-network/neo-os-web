# Neo MiniApps Platform — UI/UX 设计审计报告

**审计日期**: 2026-07-03
**审计范围**: platform/host-app, platform/admin-console, apps/* (75 个小程序)
**审计人**: UI Designer

---

## 一、现状评估

### 1.1 优势

| 维度 | 评价 |
|------|------|
| **设计系统统一性** | ✅ 有健全的 Design Token 体系 (`--ns-*` / `--mx2-*`)，跨 75 个小程序保持一致 |
| **颜色系统** | ✅ 品牌色 `#16C784` (Neo Green) 识别度高，语义色完整 |
| **排版层级** | ✅ Inter + JetBrains Mono 搭配合理，字号梯度清晰 |
| **组件库** | ✅ host-app 和 admin-console 各有 UI 组件库，小程序有 shared 组件库 |
| **无障碍** | ✅ 已有 a11y 工具文件，contrast 值经过 WCAG 校准 |
| **暗色模式** | ✅ 已有完整的 CSS 变量暗色主题定义 |
| **响应式** | ✅ 小程序有 `_app-responsive.scss`，host-app 使用 Tailwind responsive |

### 1.2 核心问题

#### 🔴 P0 — 用户第一印象薄弱

- **Hero 区域缺乏冲击力**: 首页 Hero 使用单一渐变色 + 居中文案的模板化布局，缺乏独特视觉记忆点
- **小程序卡片展示过于统一**: 所有小程序卡片使用相同的布局模式（图标 + 标题 + 描述），缺乏差异化
- **缺乏品牌叙事**: 首页缺少向新用户传达"这是什么、为什么用"的引导性内容

#### 🔴 P0 — 小程序体验碎片化

- **两套设计令牌共存**: `--ns-*`(Neo Soft v1) 和 `--mx2-*`(v2) 同时存在，新老小程序视觉风格不统一
- **小程序内部 UI 质量参差**: 部分老小程序仍使用旧版 SCSS 样式，与新设计系统脱节
- **小程序间切换体验断层**: iframe 嵌入导致切换有明显的"跳转感"，缺乏流畅过渡

#### 🟡 P1 — 导航与信息架构

- **主导航过于简单**: Navbar 仅有 3 个主链接 + 搜索，缺乏对丰富内容的合理组织
- **小程序分类不够直观**: 主页通过 Category Pills 过滤，但分类名称对非 Web3 用户不友好
- **管理控制台信息密度过高**: 仪表盘一次性展示过多数据，缺乏信息层级

#### 🟡 P1 — 交互与动效不足

- **微交互缺失**: 按钮 hover、卡片点击、页面切换缺少有意义的过渡动效
- **加载状态单调**: 仅使用基础的 Skeleton/Spinner，缺乏品牌化的加载体验
- **空状态引导不足**: 小程序未安装/未连接钱包时仅显示基础提示，缺乏引导性设计

#### 🟢 P2 — 视觉细节打磨

- **阴影系统过于保守**: `rgba(20,22,38,0.06)` 的卡片阴影在浅色背景上几乎不可见
- **圆角缺乏层次**: 所有卡片统一 `20px` 圆角，缺乏根据组件层级变化的圆角节奏
- **色彩表达单一**: 品牌色仅用于按钮和链接，缺乏更丰富的品牌色彩叙事
- **小程序 PlayArea 缺乏场景感**: 白色背景 + 居中内容的布局显得空旷且缺乏沉浸感

## 三、设计升级方向

### 3.1 指导原则

1. **品牌优先** — 让 Neo Green `#16C784` 在更多场景中自然出现，而不只是按钮颜色
2. **沉浸式体验** — 小程序 PlayArea 应该有场景感，不再是一块白色画布
3. **流畅过渡** — 小程序加载、切换、操作反馈都应有自然的动效衔接
4. **引导式设计** — 空状态、新手引导、错误提示都应有教育意义
5. **差异化表达** — 每个小程序的入口卡片应有独特视觉识别

### 3.2 具体升级计划

| 模块 | 现状 | 升级方向 |
|------|------|---------|
| **首页 Hero** | 单色渐变 + 居中文案 | 动态品牌叙事 + 数据展示 + 行动引导 |
| **小程序卡片** | 统一卡片模板 | 按分类差异化设计（游戏/DeFi/NFT/工具各有特色） |
| **PlayArea** | 白色画布 | 分类色彩氛围背景 + 场景化布局 |
| **导航** | 简单顶部栏 | 固定侧边栏(桌面) / 底部标签栏(移动端) |
| **管理控制台** | 高密度仪表盘 | 卡片化数据概览 + 快速操作 + 搜索优先 |
| **动效系统** | 基础 CSS transition | 品牌化加载动画 + 页面过渡 + 微交互 |
| **暗色模式** | 已有基础定义 | 深化暗色主题，增加品牌暗色表达 |

## 四、迁移兼容性

升级设计不会破坏现有功能：
- CSS 变量新增 `--n3-*` 命名空间（Neo v3），旧 `--ns-*` 和 `--mx2-*` 保留向后兼容
- Tailwind 预设扩展而非替换
- 小程序 opt-in 升级，老小程序继续使用现有样式
- host-app 和 admin-console 可以独立升级
