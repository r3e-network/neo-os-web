# 活动门票通行证

基于 NEP-11 的活动门票与二维码核验。

## 概览

| 属性 | 值 |
|------|----|
| **App ID** | `miniapp-event-ticket-pass` |
| **分类** | 社交 |
| **版本** | 1.3.0 |
| **框架** | Host-native React playarea |

## 特性

- 创建活动并设置票量上限
- 向参与者签发 NEP-11 门票
- 门票二维码展示用于入场核验
- 创建者/网关核销门票并标记已使用
- 从已核验的钱包票夹转赠未使用门票
- 交易事件与合约权威状态双重核验
- 活动发现与真实的主办方邀请签发模型
- 所有写操作均保存准确交易并支持刷新恢复
- 恢复记录只有在本地删除回读成功后才会清除
- 主办方、接收方、检票方与转赠地址统一使用规范脚本哈希参数
- 运行时核验网络、合约校验和、NEP-11、ABI 与宿主绑定
- 基于所选活动已签发 Token 重建主办方入口队列，并与持有人个人票夹严格分离

## 用户流程

1. **发现活动**：浏览合约中仍在进行且未过期的活动。
2. **接收通行证**：由活动主办方向参与者钱包签发 NEP-11 门票。
3. **打开票夹**：持有人查看已逐张核验的通行证和真实二维码 Token ID。
4. **入口核验**：主办方从活动入口队列选择或扫描 Token，先复核实时状态，再标记为已使用。
5. **恢复交易**：若交易已广播但仍在索引，刷新后继续恢复同一 txid，不会重新发起写入。

## 生产行为

- 交易仅广播但未观察到匹配事件时，不会显示成功或改写本地票务状态。
- 创建、签发、核验、启停和转赠都必须匹配活动、Token、主办方或接收方，并通过合约状态回读。
- 签发给其他钱包的通行证不会伪装成主办方“我的门票”。
- 钱包票夹扫描有明确上限；无法证明完整余额时会显示“部分核验”，不会声称错误总数。
- 入场核验采用两步流程：先查询并查看实时票务状态，再标记为已使用。
- 签名前会核验明确钱包网络、脚本哈希、部署 NEF 校验和 `2976433161`、NEP-11 声明、所需方法/事件签名，以及宿主通道的 `symbol=TICKET`、`decimals=0` 读取。
- 交易广播时会立即保存准确 txid；待确认操作恢复前会阻止第二次写入。
- 链上应用日志若明确为 VM `FAULT`，界面会报告失败并清除该终态待处理记录；日志尚不可用时则继续如实显示等待确认。
- 钱包或网络切换会使旧账户的进行中读取失效，清空旧钱包视图，并在重新核验链上下文后加载新数据。
- 活动发现与主办方活动列表采用完整快照：任何预期详情读取失败都不会悄悄发布残缺列表。
- 扫描 Token、钱包、网络或合约在读取期间发生变化时，旧的入口查询结果会被丢弃。
- 创建、签发、启停、核验与转赠共用一个写入锁，不会在首笔 txid 尚未记入恢复日志前并发弹出第二个钱包请求。
- 钱包连接与交易恢复也受同一忙碌边界保护；冲突操作会明确提示正在处理，不再静默忽略。
- 活动 ID 始终按整数安全字符串处理；零时长活动会在签名前拒绝，标准 `Hash160` 参数统一使用框架规范构造器。
- 链上结果已核验但恢复记录删除回读失败时，操作会继续保留为待处理，用户可重试清理而不会重放交易。
- 入口队列从所选主办方活动的已签发 Token 重建，不会把当前持有人的个人票夹冒充为宾客队列。

当前部署合约没有付费购票或参与者自主领取方法，因此公开活动明确标注为“主办方邀请签发”，界面不会提供虚假的购买或领取按钮。

本版本仅复用仓库已有的 `pass-artwork.webp`、`logo.webp` 与 `banner.webp`，没有从外部游戏或参考仓库复制素材。
