# 二次方资助 MiniApp

这是一个 Neo N3 公共物品资助工作台：社区可以创建限时轮次、登记项目、使用 NEO 或 GAS 捐助、复核链下匹配建议、链上结算，并由项目负责人领取资金。

## 真实的业务边界

- 合约记录轮次、项目、每个钱包的捐助、钱包数、匹配分配和领取状态。
- 捐助只能在轮次有效时间内进行。
- 当前源码禁止项目负责人和轮次创建者向关联项目捐助。
- 轮次结束后，仅平台管理员（或已配置网关）可结算。
- 最终匹配金额由链下提供；合约只验证项目、非负金额、项目不重复以及总额不超过匹配池。
- `contributorCount` 统计的是钱包地址，不代表经过验证的独立真人。

## 匹配预览

精确 CLR 需要每位捐助者的金额 `cᵢⱼ`：

```text
补贴权重ᵢ = (Σⱼ √cᵢⱼ)² − Σⱼ cᵢⱼ
```

当前读接口只暴露总额 `Tᵢ` 和钱包数 `nᵢ`，因此前端明确标记为“汇总估算”，并使用等额假设下的简化公式：

```text
估算权重ᵢ = max(nᵢ − 1, 0) × max(Tᵢ, 0)
```

匹配池按权重比例分配，并使用最大余数法处理最小单位的取整尘埃。已停用项目和仅有一个钱包的项目获得 0 建议额。平台管理员必须在结算前复核。

## 生产交易准备

资金操作需要两笔交易：先向合约预付 NEO/GAS 信用，再调用消耗操作。生产部署必须暴露 `directAssetCreditOf` 和 `reclaimDirectAssetCredit`，否则第二笔交易失败时可能没有取回余额的通道。在批准任何部署开放写入前，合约还必须提供应用级取回事件，前端也必须开放 `TESTNET_STATUS.md` 中列出的取回与退款路径。

截至 2026-07-11，主网和测试网配置的 `0xe2fba2a73cf92874ecc41b7fff8d3d5da0354c43` 都是旧版部署（`updatecounter: 0`），不包含上述恢复方法。前端会主动探测能力，缺失时进入探索模式。仅有方法响应和稳定脚本哈希仍不足以启用写入，因为 Neo 升级会保留地址：对应的 `network:contract:code-fingerprint` 必须完成生产生命周期验证。当前生产构建未批准任何部署，因此不会开放合约写入，也不会因为“配置了合约地址”就发送资金。

公共轮次与项目浏览不需要连接钱包；项目使命、HTTP(S) 项目链接、捐助总额和匹配结果仍可实时查看。已结算轮次展示链上实际分配，未结算轮次才展示汇总估算。

详见 [TESTNET_STATUS.md](./TESTNET_STATUS.md) 与 [PRODUCTION_STATUS.md](./PRODUCTION_STATUS.md)。

## 验证

每个支持的写操作都会等待精确合约事件，然后读回受影响的轮次、项目或捐助记录。只有交易 ID 但没有精确事件/读回时，界面会显示“待确认”，不会误报为完成。
