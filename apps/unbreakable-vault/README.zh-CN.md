# 坚不可摧保险库

一个以保险库资产为核心的 DeFi 悬赏应用。创建者用 SHA-256 摘要托管 GAS；
挑战者先查看精确资产、费用、到期时间与状态，再按合约难度费用尝试密钥。

## 核心流程

1. 选择悬赏、难度、标题、公开提示，并输入两次一致的密钥。
2. 浏览器在本地计算创建密钥的哈希；`createVault` 只接收 32 字节摘要。
   明文不会持久化，也不会写入交易恢复记录。
3. 分享经过事件和回读验证的保险库编号。挑战者加载权威状态后再尝试。
4. 失败尝试会增加悬赏；正确尝试会在扣除 2% 协议费后，原子化向获胜者
   支付托管额的 98%。未破解且到期的保险库可由创建者取回 98%。
5. 任何人都可在次级保险库面板为有效目标追加悬赏。

## 交易正确性与恢复

每次写入都要求检测到明确的钱包网络，并精确绑定规范合约、连接钱包、
保险库编号、fixed8 字符串金额、合约暂停/支付配置、事件槽位和
`getVaultDetails` 权威回读。大额资产不会经过 JavaScript 浮点数转换。

测试网采用两笔交易：先转 GAS，再调用业务方法。应用会保存支付/业务
交易 ID，并在上一笔操作解决前阻止新写入。如果只广播了支付，恢复操作
只调用业务方法，不会再次支付。尝试密钥不会保存，因此恢复已支付的破解
尝试时需要用户重新输入。

恢复记录中的绑定值只是确定性的损坏/结构校验，并不是签名。产品确认依赖
规范网络与合约、精确匹配的 HALT GAS 转账、钱包选择的签名账户、合约按
memo 区分的预付额度，以及精确事件和权威回读。

所有写操作共用一个操作锁，并在广播前冻结已确认的钱包、网络、保险库、
金额与密钥输入。目标或钱包发生变化会在请求新交易前中止。若广播后存储
失败，必须先把同一份内存交易记录持久化并验证回读，才能继续恢复或再次支付。

主网 ABI 的创建、破解、追加悬赏方法都带有尾部 PaymentHub 收据 ID。
当前主网合约尚未配置 PaymentHub，因此主网如实保持只读。配置完成后，
资金写入必须填写有效的已结算收据；应用不会误用测试网参数形状。
