# Graveyard / 记忆花园

一个明亮、庄重、隐私优先的 Neo N3 记忆承诺应用：先埋葬记忆摘要，之后可以选择将它标记为“已遗忘”。

## 产品流程

1. 选择私密文字、本地文件或已有 SHA-256 摘要。
2. 文字和文件通过 Web Crypto 在本设备计算哈希；原文和文件字节不会上传，也不会传给合约。
3. 选择五种链上记忆类型之一，并在签名前检查钱包、合约实时费用、摘要与永久记录提示。
4. 在钱包中确认。应用先存入埋葬费用，再调用 `buryMemory`；只有 `MemoryBuried` 事件确认后才显示成功。
5. 历史记录之后可以添加墓志铭，或通过独立的付费确认标记为“已遗忘”。

## 合约语义

| 操作 | 路径 | 结果 |
|---|---|---|
| 埋葬 | 使用 memo `miniapp-graveyard:memory` 存入 GAS，再调用 `buryMemory(owner, contentHash, memoryType)` | 发出 `MemoryBuried` |
| 墓志铭 | 签名调用 `addEpitaph(memoryId, epitaph)`，不收取 Graveyard 应用押金 | 发出 `EpitaphAdded`；仍可能产生普通 Neo 网络费 |
| 遗忘 | 使用相同 memo 存入 GAS，再调用 `forgetMemory(owner, memoryId)` | 发出 `MemoryForgotten` |

“遗忘”**不会**删除事件日志或内容哈希，只会在原有审计轨迹中永久记录已遗忘状态。当前费用从 `getPlatformStats` 读取；两项实时费用核验完成前，所有付费操作保持禁用，因此 0.1/1 GAS 的初始显示绝不会授权过期费用转账。

## 隐私与错误恢复边界

- 付费埋葬只接受 64 位 SHA-256 摘要。
- 本地文件最大 25 MB，只在计算摘要期间读取。
- 只有 `MemoryBuried` 事件验证后才清空已准备内容。钱包拒绝和广播前失败可以重试；若交易已广播但事件仍未验证，应先刷新记录再提交。
- 没有显式检查弹层就无法调用付费埋葬；摘要、记忆类型或费用变化会使上一次确认失效。
- 埋葬和遗忘只有在各自合约事件验证后才更新界面；墓志铭还必须通过 `getMemoryDetails` 精确回读。仅有已广播交易 ID 或事件都不会显示为成功。
- 事件必须与检查内容逐项一致：记忆 ID、所有者、摘要、记忆类型和墓志铭文本不匹配时不会更新本地状态。
- 实时费用读取失败时，检查操作保持禁用并提供明确重试；不会把备用费用发送到钱包。
- 应用会与费用同时读取实时 `isPaused` 状态；合约暂停或状态不可读时，会在转移 GAS 前阻止付费操作。
- 若 GAS 押金已广播但后续合约调用未完成，设备本地恢复日志会恢复摘要/类型，并在直接重试时复用该额度，不会再次收取押金；等待事件的目标交易会通过钱包范围内的记录进行核对，同时阻止重复付款。日志绝不保存原文或文件字节。
- 墓志铭广播后会按钱包保存记忆 ID、完整文本与交易 ID，并转为只读的“检查状态”任务；合约回读一致前不会再次打开签名。
- 打开任何钱包写入前，恢复日志必须完成一次本地存储读写校验。存储不可用时写入保持禁用，但只读记录仍可继续查看。
- 切换钱包时会先清空上一位所有者的记录；即使新钱包读取失败，也不会残留展示其他钱包的历史。
- 应用不会加密、保存、上传、删除或销毁原始文字/文件，也不提供 TEE 密钥销毁。

公开 manifest 特意不再提供通用参数表单。埋葬、墓志铭和遗忘都只在设计好的“记忆花园”工作区完成，使来源、实时费用、确认和恢复状态保持在同一条体验中。
