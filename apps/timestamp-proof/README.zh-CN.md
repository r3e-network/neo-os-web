# Timestamp Proof 时间戳证明

`Timestamp Proof` 是一个本地 SHA-256 证明记录工具，并支持可选的 Neo N3 上链锚定。

## 当前行为

- 在浏览器本地计算内容的 `SHA-256` 哈希
- 将证明记录保存在当前设备的浏览器本地存储中，并在提示成功前进行写入回读校验
- 将读取失败、记录损坏与真正的空记录明确区分，不会覆盖无法读取的已有记录
- 为每条证明生成本地 proof id，方便之后查询
- 支持通过 proof id、摘要或原文重新打开本机证明
- 支持检查便携 JSON 引用，并在选定的 Neo N3 网络上独立核验已锚定引用或交易 ID
- 在连接钱包后，可以用真实的 0 GAS 自转账把已保存摘要锚定到 Neo N3
- 当 manifest 明确提供已部署的 PlatformSocial 共享引擎绑定时，也支持租户隔离的 Notary 路径；当前生产 manifest 没有该绑定，因此仍使用 0 GAS 路径
- 广播后先把回执持久化为 `pending`；只有当前锚定方式对摘要、钱包与公开链上时间的独立核验全部通过后，才会升级为 `anchored`
- 钱包提交中断时保留持久重试锁，页面重载后也不会盲目重复提交
- 页面重载时会重新核验已保存的锚定声明；回执待确认或提交中断的记录在解决前不可删除

## 隐私与可信边界

- 原始内容保留在用户设备上
- 本地证明是私密且免费的
- 本地时间戳来自设备时钟，在该浏览器配置之外不能被独立信任
- 当前锚定只会在公开交易数据中写入 `timestamp-proof:<摘要>`；未来启用 Notary 后会在租户隔离的合约状态与事件中公开摘要和提交者
- 交易 ID 只代表广播回执，不代表交易已经确认
- 未锚定的便携 JSON 引用只是结构化本地声明，并非可独立信任的时间戳证据
- 旧锚定通过应用日志和原始交易脚本核验；已配置的 Notary 锚定通过不可变的租户合约状态核验；确认链上时间即公开证明时间
- 原生 GAS 转账使用钱包地址对应的规范脚本哈希，并拒绝格式异常或钱包不匹配的事件绑定
- 本地证明只存在于创建它的浏览器配置中，清理浏览器存储会删除记录

## 使用方式

1. 输入文本、文档哈希或简短证明备注。
2. 创建本地证明条目。
3. 复制便携证明引用，或通过 proof id、摘要、原文重新打开本机记录。
4. 可选：连接 Neo N3 钱包并锚定最新证明；提交前会明确提示少量网络费。
5. 如果回执仍待确认，请在下一个区块后检查，不要重复提交。
6. 检查 JSON 引用；如果其中包含锚定回执，则在记录的网络上核验该回执。

如果记录不可用，请恢复浏览器本地存储访问后重试；应用会明确显示“不可用”，不会伪装成 0 条记录。如果钱包提交在记录交易 ID 前中断，请先检查钱包历史，再清除重试锁。

## 不做什么

- 不上传原始文档
- 不把原文内容写入链上
- 不把本地证明伪装成公开链上证据
- 核心本地证明流程不依赖 Oracle 或 AA

## 技术细节

- 类型：前端工具，可选钱包交易
- 哈希函数：`SHA-256`
- 本地存储：浏览器 localStorage
- 锚定方式：当前为携带 `timestamp-proof:<摘要>` 的 0 GAS 自转账；明确绑定已部署 PlatformSocial 后可走受保护的 Notary 路径
- 支持网络：Neo N3 主网与测试网
- 回执状态：`local → preparing → pending → anchored | fault`

生产边界与验证结果见 [PRODUCTION_STATUS.md](./PRODUCTION_STATUS.md)、[NETWORK_STATUS.md](./NETWORK_STATUS.md) 和 [ASSET_PROVENANCE.md](./ASSET_PROVENANCE.md)。

## 后续升级路径

PlatformSocial Notary 已在源码与前端双路径中实现，但当前生产 manifest 仍未绑定，因为没有部署记录。必须先部署、注册 Timestamp Proof 租户并验证精确工件、ABI 与恢复流程，再在单独审批的变更中加入共享绑定。不要在没有真实部署依据的情况下使用合成交易 ID 或伪合约调用。
