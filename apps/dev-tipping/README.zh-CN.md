# 开发者打赏

开发者打赏是一个以收款对象为核心的 GAS 支付 MiniApp，由已部署的 `MiniAppTipJar` 合约提供链上结算。

## 产品流程

1. 先验证当前 Neo N3 网络对应的已发布合约版本。
2. 从支持看板选择已注册开发者；直接输入开发者 ID 收进次级抽屉。
3. 选择 GAS 快捷金额，或输入最多八位小数的自定义金额。
4. 核对开发者身份、注册钱包、金额、署名设置和已验证钱包 GAS 余额。
5. 在钱包中确认一次资金与打赏操作。
6. 交易哈希仅表示“已广播”；必须由精确 `Tipped` 事件与接收方状态读回共同确认成功。

已部署合约只记录开发者 ID、发送地址、Fixed8 金额和匿名标志，不会存储自由文本留言或发送者昵称。

## 交易与恢复

- 最低打赏为 `0.001 GAS`（`100000` Fixed8 基础单位），并通过 `minTip()` 在线核对。
- 支付前会读取已有预存额度；RPC 失败不会被当作零，也不会继续重复充值。
- 如果预存额度只覆盖部分打赏，钱包只补足精确差额，不会再次充值整笔打赏金额。
- 支付前从官方 GAS NEP-17 合约读取钱包余额。
- 待确认收据按网络、合约和发送者隔离并持久化。
- 只有发送者、开发者 ID、金额、署名标志和 `getDeveloper` 总额/次数读回全部匹配，才显示“已确认”。
- `FAULT`、仍待确认、HALT 但事件缺失、读回延迟、收据过期和预存额度滞留均有独立恢复状态。
- 如果充值已落链而 `tip()` 失败，额度仍保留在合约中，可通过额度取回路径恢复。
- 开发者注册、开发者领取和未使用额度取回，与打赏一样使用精确交易哈希日志、事件核对和状态读回恢复。
- 过期收据仍保持锁定，不能仅因时间经过就允许重复操作。

## 资源

- `public/support-board-stage.webp`：现有的明亮开发者支持台主视觉，同时作为目录与 Open Graph 封面。
- GAS 金额统一使用共享 `CoinArt`；`apps/shared/test/official-token-assets.test.tsx` 将其锁定为 Neo Press Kit 官方 GAS 资源。
- 界面图标沿用仓库 Lucide 控件体系，不冒充头像或 Token 美术。

## 开发

```bash
npm test
npx tsc -p tsconfig.json --noEmit
npm run build
```

本版本不包含 Oracle、TEE、AA 中继、部署操作或服务端托管资金。

当前实现、网络验收边界与资源记录分别见 `PRODUCTION_STATUS.md`、`NETWORK_STATUS.md` 和 `ASSET_PROVENANCE.md`。
