# 红包

红包是一款 Neo N3 拼手气社交应用，核心领取过程由明亮喜庆的 Phaser 场景呈现。创建者把 GAS 锁入 1–100 份红包，分享红包 ID／链接；每个钱包只能领取一次。过期后，创建者可以回收尚未领取的 GAS。

分享链接是**公开持有者链接**，不是私密访问控制：任何知道或猜到对应网络与红包 ID 的钱包，都可以在尚有余额时领取一次。应用不会展示全局“最新红包”列表；真正私密或限定收件人的红包需要新合约支持。

## 当前真实流程

1. 在 Phaser 红包桌面选择一个设计好的低风险红包套餐。
2. 单独连接钱包；连接动作不会顺带花费 GAS。
3. 创建红包。应用只补足缺少的 GAS 额度，确认到账后再创建精确红包。
4. 分享生成的、绑定网络的红包链接。
5. 每个已连接钱包打开一份随机红包。只有精确领取交易确认后，才播放庆祝动画并显示金额。
6. 过期后创建者可回收精确的未领取余额；未使用的创建额度也可随时提取。

当前只有拼手气模式。已部署合约不支持祝福语、均分、NEO 持仓门槛、自动退款或“手气最佳额外 5%”；界面和文档不得承诺这些并不存在的能力。

## 随机性与边界

合约在领取时使用 Neo `Runtime.GetRandom()`，配合双倍均值上限，并为每个后续红包至少保留一个基础单位。这不是预言机／VRF 级随机性：高级领取者理论上可能跨区块中止并重试，让自己的结果更接近上限。

因此 v1.1 合约强制限定为低风险社交赠礼：

- 每个红包最多 20 GAS；
- 最多 100 份；
- 有效期 60 秒到 7 天；
- 非最后一份金额受约两倍实时均值限制；
- 全部领取金额加创建者回收额严格等于总充值额。

高价值公平抽奖应使用 VRF／提交揭示产品。红包在上述边界内优先保证一次点击即可领取的社交体验。

## 公开 ABI

| 方法 | 用途 |
| --- | --- |
| `createEnvelope(creator,total,packets,duration)` | 消耗预付额度并创建足额拼手气红包 |
| `claim(envelopeId,claimer)` | 每个钱包领取一次，并原子收到随机份额 |
| `reclaim(envelopeId,creator)` | 过期后回收未领取余额 |
| `withdraw(account)` | 提取未使用的创建额度 |
| `getEnvelope(id)` | 读取红包状态与手气最佳信息 |
| `creatorEnvelopeCount` / `getCreatorEnvelopes` | 分页读取创建记录 |
| `claimerEnvelopeCount` / `getClaimerEnvelopes` | 分页读取领取记录 |
| `claimedAmount` / `hasClaimed` | 读取钱包的精确领取状态 |

## 部署

| 网络 | 合约 | 状态 |
| --- | --- | --- |
| Neo N3 测试网 | `0x5a5ecc80cd5225acd7431a5dd6f0e32bb9260a87` | v1.1 有界合约；2026-07-10 已完成双钱包真实流程验证 |
| Neo N3 主网 | `0x363c5de9760d1aaaed5096fdf3bdc877cd0368e9` | 旧版无上限合约；暂停新建，已有领取／回收／提取仍可用 |

网络映射以 [`neo-manifest.json`](./neo-manifest.json) 为准。
每次付费操作前，应用还会验证网络、脚本哈希、已部署 NEF 校验和、合约版本和必需 ABI；验证失败或 RPC 不可达时保持禁用，不会让动画或广播结果冒充到账成功。

## 开发

```bash
cd apps/red-envelope
npm test
npm run build
npm run dev
```

免费模式是完全本地的开红包游戏，不会调用钱包、合约、预言机或奖励写入。
