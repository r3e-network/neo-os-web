# Neo 签名工作台

Neo 签名工作台用于准备 Neo N3 钱包消息签名所需的精确 UTF-8 载荷。它支持文本与本地 SHA-256 文件摘要，在钱包确认前展示完整载荷，并把钱包返回结果导出为可携带 JSON 签名记录。

## 运行约束

- App ID：`miniapp-neo-sign-anything`
- 版本：`1.1.0`
- 网络：Neo N3 主网与测试网
- 权限：`wallet:sign-message`
- 交易：无
- 小程序合约：无

## 签名模式

默认使用“用途绑定信封”。v1 签名信封会绑定：

- 签名域；
- Neo N3 网络；
- 本次钱包请求捕获的签名账户；
- 内容类型、UTF-8 字节数与 SHA-256；
- 载入文件摘要时的文件名、字节大小、媒体类型与文件 SHA-256。

“原文直签”会逐字节签署文本框中的 UTF-8 内容。它仅适用于第三方要求完全相同挑战字符串、不能增加信封的场景。

在“原文直签”模式中，捕获的账户与网络只属于请求上下文，并未写入签名字节。连接钱包之前即可核对原文载荷与 SHA-256；真正签名时仍必须确认 Neo N3 账户与网络。

## 文件处理

最大 64 MB 的文件会通过浏览器 Web Crypto 在本地读取并计算哈希，不会上传。编辑器中只会写入 `sha256:<小写十六进制摘要>`；用途绑定信封还会加入界面展示的文件元数据。

## 签名记录语义

JSON 记录包含精确签署文本、字节数、SHA-256、捕获的账户与网络、规范化签名编码，以及钱包提供时的公钥。`signer.binding` 会明确区分 `signed-envelope`（上下文已签入）与 `observed-request-context`（仅观察到的请求上下文）。

可信度状态明确标为 `wallet-returned`。本工具不会声称已经在本地完成密码学验签，因为不同 Neo 钱包可能采用不同的消息签名传输与验证约定。验证方必须使用签名钱包对应的规则。

如果钱包确认期间账户、网络、内容、签名域或文件上下文发生变化，返回签名会被丢弃。钱包提供实际签名账户时，该账户必须以地址或脚本哈希形式与准备账户一致，否则响应会被拒绝。修改任何已签输入也会立即清除当前记录。替换文件失败时，旧文件摘要会被清除，避免被误认为是刚选择文件的摘要。

## 链与预言机边界

- 当前网络只从已连接钱包读取，并规范化为 `neo-n3-mainnet` 或 `neo-n3-testnet`；其他值会按失败关闭处理，并清除界面中的网络值。
- 应用只调用框架的钱包连接、网络检测和消息签名服务。
- 不包含小程序合约、RPC 查询、预言机请求、交易构造、广播、代币转账或网络手续费流程。
- 签名或文件哈希失败时会保留可修正的用户文本；上下文过期或含糊的签名结果会直接丢弃。

## 本地历史

应用最多在框架隔离的本地存储中保留八条历史记录。历史只保存记录元数据与哈希，不保存原始消息、签名、公钥或完整 JSON 记录。格式异常的本地记录会被忽略，界面会提示历史存储降级，但不会阻断签名。
